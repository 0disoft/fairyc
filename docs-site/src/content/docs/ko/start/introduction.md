Fairy C는 가비지 컬렉터 없이 네이티브 제어권을 유지하면서, 자원 수명, 빌림 규칙, 정수 오버플로, 부수 효과 경계를 컴파일 타임에 검사하는 실험적 시스템 프로그래밍 언어입니다.

## 핵심 특징

- **명시적인 자원 소유권**: 이동 전용 `resource` 타입에 `cleanup` 블록을 정의해 결정적인 해제를 보장합니다.
- **컴파일 타임 빌림 검사**: 공유 참조(`ref T`), 가변 배타 참조(`ref mut T`), 슬라이스 뷰(`u8[]`)의 수명과 겹침을 검사합니다.
- **검사된 정수 산술**: 오버플로와 0으로 나누기를 조용히 감싸지 않고 트랩(trap)으로 처리합니다.
- **선언적 효과 표기**: 콘솔, 파일시스템, 시계 같은 외부 상호작용에 `@effects(...)`를 명시합니다.
- **직접적인 C 연동**: `@repr(C)` 구조체, `unsafe extern C fn`, 명시적 `unsafe` 블록으로 C 라이브러리와 Win32 API에 직접 연결합니다.

## 적합한 용도와 현재 한계

작은 네이티브 CLI 도구, C ABI 래퍼, 자원 정리가 중요한 Win32 데스크톱 프로그램처럼 작고 결정적인 바이너리를 작성하는 실험에 적합합니다.

반면 현재 컴파일러는 **Stage 0 프로토타입**이므로, 모든 플랫폼에서의 공식 타깃 적합성 인증, 사용자 제네릭·클로저 완성판, 원격 패키지 레지스트리 생태계는 아직 갖추어지지 않았습니다.

## Fairy C와 Brownie C의 차이

| 구분 | Fairy C (`.fy`) | Brownie C (`.brc`) |
| --- | --- | --- |
| 성격 | 네이티브 시스템 프로그래밍 언어 | 임베디드 규칙·바이트 변환 언어 및 VM |
| 실행 방식 | C11 백엔드와 C 툴체인으로 네이티브 실행 파일 생성 | 내부 바이트코드 검증 후 제한된 VM에서 실행 |
| 구현 기반 | Go로 작성된 Stage 0 컴파일러(`fairyc`) | Fairy C로 구현 중인 런타임(`browniec`) |
| OS·C 연동 | `unsafe extern C fn` 및 표준 라이브러리 I/O 사용 | 임의 FFI 및 직접적인 OS 파일·네트워크 접근 불가 |
| 주 사용처 | CLI 유틸리티, Win32 앱, 네이티브 엔진 | 예산(Fuel) 제한 하의 결정적 규칙 평가 |

## 설계 목표, 공개 CLI, 내부 실험 명령 구분

저장소 문서와 도구를 볼 때는 다음 세 층위를 구분해야 합니다.

1. **공개 안정 CLI (`fairyc`)**: `new`, `check`, `build`, `run`, `test`, `explain`, `targets` 명령으로 `fairy.toml` 및 `fairy.lock` 기반 패키지를 다룹니다.
2. **내부·실험 명령 (`fairyc experimental ...`)**: `emit-c`, 시맨틱 인터프리터 `run`, `atlas-*` 코드 분석 명령은 컴파일러 개발용 실험 인터페이스이며 안정 계약이 아닙니다.
3. **공식 타깃 적합성 목표**: `fairyc targets` 출력은 현재 `x86_64-windows-msvc`와 `x86_64-linux-gnu` 모두 `supported: no`로 표시합니다. 로컬 C 툴체인이 준비되어 있으면 실제 빌드·실행은 동작하지만, 전체 표준 라이브러리와 ABI 적합성 증명이 완료된 상태는 아닙니다.
