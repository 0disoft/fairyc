개발할 때 실제로 자주 쓰게 되는 `fairyc` 명령어와, 에러 코드가 떴을 때 당황하지 않고 고치는 방법을 정리했습니다.

## 자주 쓰는 명령어

| 명령어 | 언제 쓰나요? |
| --- | --- |
| `fairyc new <이름> --uid <고유ID>` | 새 패키지 프로젝트 폴더를 처음 만들 때 |
| `fairyc check [--locked]` | 실행 파일은 안 만들고 문법·타입·빌림 검사만 빠르게 돌릴 때 |
| `fairyc build [--release] [--locked]` | `build/<이름>.exe` 실행 파일을 폴더에 생성할 때 (`--release`는 최적화) |
| `fairyc run [--release] [--locked] [-- <인자...>]` | 임시로 빌드해서 바로 실행해 보고 싶을 때 |
| `fairyc test [--native] [--locked]` | `tests/` 아래 테스트를 인터프리터(기본) 또는 네이티브 바이너리(`--native`)로 돌릴 때 |
| `fairyc explain <에러코드>` | 컴파일러가 뱉은 `E2101` 같은 코드의 뜻이 궁금할 때 |

`fairyc experimental ...` 명령들은 컴파일러 개발자용 실험 명령이므로 일반 프로젝트에서는 위 기본 명령들만 쓰시면 됩니다.

## 종료 코드 빠르게 읽기

명령이 실패했을 때 프로세스 종료 코드만 봐도 어디서 막혔는지 감을 잡을 수 있습니다.

- **`0`**: 성공 (`run`에서는 내 프로그램도 `0`을 반환한 경우)
- **`2`**: 명령어 옵션이나 인자를 잘못 적음
- **`3`**: 내 코드에 문법·타입·빌림·`@effects` 오류 있음
- **`5`**: 실행 도중 정수 오버플로, 0으로 나누기, `assert` 실패로 멈춤(trap)
- **`6`**: C 컴파일러(MSVC / GCC / Clang)를 못 찾았거나 링크 실패
- **`7`**: `fairy.toml`이나 `fairy.lock`이 맞지 않음 (`check` 다시 실행 필요)

## 자주 만나는 오류와 해결법

에러 메시지에 코드(예: `E2101`)가 나오면 터미널에 `fairyc explain E2101`을 쳐서 자세한 설명을 볼 수 있습니다. 자주 부딪히는 몇 가지를 예로 들면 다음과 같습니다.

1. **`E1001` — 변수 초기화 빠짐**: `var i32 count;`처럼 선언만 하면 안 됩니다. `var i32 count = 0;`처럼 초기값을 꼭 넣어 주세요.
2. **`E1006` / `E0009` — 타입 섞임 또는 연속 비교**: `usize`와 `i32`를 그냥 더할 수 없으니 `as i32`로 변환하고, `0 < x < 10` 대신 `(0 < x) && (x < 10)`으로 괄호를 넣어 주세요.
3. **`E1101` — 이미 넘긴 `resource` 또 사용**: 함수에 값으로 넘겨준 자원을 뒤에서 다시 쓰면 납니다. 호출 뒤에도 써야 한다면 매개변수를 `ref`나 `ref mut`으로 바꿔 보세요.
4. **`E2101` — 빌린 동안 원본 수정**: `let r = ref data;`로 빌려놓고 아래에서 계속 쓰는데 중간에 `data`를 고치려고 하면 납니다. 읽기 참조(`ref`) 사용이 끝난 뒤 수정하세요.
5. **`E4101` — `Result` 결과 안 챙김**: 파일 열기나 `io::write`의 `Result`를 그냥 무시하면 에러가 납니다. `switch`, `?`, 또는 `discard`로 처리하세요.
6. **`E7102` — `@effects(...)` 누락**: 콘솔이나 파일을 건드리는 함수를 불렀는데 내 함수 선언 위에 `@effects(console)` 등을 안 적었을 때 발생합니다.
