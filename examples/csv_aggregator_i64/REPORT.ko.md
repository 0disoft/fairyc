# i64 CSV 집계 검증

기존 03-csv-aggregator 원본과 배포본·실행 증거는 보존하고 저장소 안에
독립 예제를 추가했다. 숫자 파서의 반환값, 누적 합계, 최솟값·최댓값을
`i64`로 확장했다. CSV 해석과 숫자 계산은 Fairy C로 수행한다.

음수 상태로 자릿수를 누적해 최솟값을 읽는다. 곱셈·뺄셈 이전에 범위를
검사하고 합계 덧셈 이전에 허용 범위를 검사한다. SDK stage0.73의
`append_i64`와 `write_bytes`를 이용해 최솟값도 정확히 출력한다.

`internal/cli/i64_csv_test.go`의 고정 정답 15개를 Windows AMD64 MSVC
일반(low)·최적화(optimized) 프로필에서 각각 실행한다. 검사 대상은
stdout 전체, stderr 전체, 종료 코드이며 실패 입력의 빈 stdout도 확인한다.

| 사례 | 요구 결과 |
| --- | --- |
| i32 최댓값 두 개 | 합계 4294967294 |
| 양수·음수 32비트 초과 값 | 합계 10000000000 |
| i64 최솟값·최댓값·두 값의 합 | 정확한 출력, 두 값의 합은 -1 |
| 부호 있는 0·긴 선행 0 | 0 |
| 따옴표·공백·두 번째 열 | 합계 0 |
| 최댓값 + 1·최솟값 - 1·긴 숫자 | 입력 범위 오류, 종료 1 |
| 양수·음수 합계 초과·후반 합계 초과 | 합계 오류, 종료 1 |
| 소수·빈 숫자 | 문법·빈 값 오류, 종료 1 |

원시 결과와 입력·소스 SHA256, 두 EXE SHA256은
[검증 기록](../../docs/ops/evidence/i64-csv-20261001.json)에 보관한다.
전체 기존 CSV 검증이나 성능 실험을 반복하지 않았다.

큰 정수 리터럴이 이항 연산 왼쪽에서 우측 타입을 받지 못하는 제약은
남아 있다. 합계 범위 검사는 명시적 `i64` 변수로 작성했다. 참조 재대여,
가변 슬라이스 subview, 반복 배열 초기화, 좌변 리터럴 추론은 별도 후속
작업이다. 이번 변경은 저장 내구성이나 전원 장애 복구를 검증하지 않는다.
