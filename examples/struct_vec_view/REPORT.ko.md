# 중첩 구조체 스칼라 필드 대입 구현 결과

ADR 0442 규격에 따라 가변 지역 구조체 및 `ref mut` 수신자의 중첩 스칼라 필드를 직접 수정할 수 있도록 지원합니다. ADR 0441에서 정의된 공유 뷰와 값 복사 기반 순회 기능도 함께 유지됩니다.

```fairy
var Token copy = view[0];
copy.position.start = 10;
copy.position.end += 1;
```

`src/tokens.fy`의 `rebase` 함수는 복사된 토큰의 시작·끝 위치에서 기준점(origin) 오프셋을 차감하고, `analyze` 함수에서 해당 지역 위치값을 검증합니다. 렉서가 파싱하여 저장한 원본 토큰 데이터와 출력 결과는 안전하게 보존됩니다. 실제 핵심 연산 로직은 Fairy C로 작성되었으며, Python 스크립트는 공개 CLI 검증 용도로만 사용됩니다.

이름이 명시된 가변 루트와 일반(plain) 중첩 구조체의 스칼라 리프(leaf) 필드에 한해 수정을 허용합니다. 공유 또는 불변 루트이거나, 활성 상태의 루트·필드 대여가 남아있는 경우에는 변경이 엄격히 제한됩니다. 배열 원소, 함수 호출 결과, 리소스 루트, 참조나 포인터를 경유하는 경로, 구조체 필드 전체 대입 및 가변 필드 대여는 이번 단계의 지원 범위에 포함되지 않습니다. 기존 직접 스칼라 필드/리소스 및 단일 usize 래퍼 대상 대입 규격은 그대로 유지됩니다.

MIR 단계에서는 루트 식별자와 조상 필드 목록, 리프 이름을 보존하여 실제 정의 및 지역 타입을 검증합니다. C 코드 생성 단계에서는 중첩 lvalue를 직접 수정하고, 인터프리터 환경에서는 메모리상의 유효한 중첩 셀을 변경합니다. 중간 구조체를 불필요하게 복사하여 수정 내용이 유실되는 lowering 결함은 발생하지 않습니다. 복합 대입(compound assignment)은 우변(RHS) 평가 전에 기존 값을 먼저 읽고 우변 표현식을 정확히 한 번 실행합니다. 우변에서 `var ref mut`이 재바인딩되더라도 최초에 선택된 원래 대상에 기록되며, 쓰기 완료 시점까지 해당 대여 상태를 유지합니다. 산술 연산 실패 시에는 메모리 쓰기 전에 트랩(trap)이 발생합니다.

## 검증 내역

- **Windows 기본(low) 및 릴리스(release) 환경**: 중첩 대입 테스트 11건씩 총 22회 네이티브 실행 통과. 6종 스칼라 타입, 정수 복합 연산, 복사 독립성, 우변 평가 순서 및 횟수, 참조 재지정과 지역 소유자 교체, 오버플로/언더플로, 0 나눗셈, 비정상 상수 시프트 오류를 종합 검증했습니다.
- 소스 수준 거부 테스트 12건, 위조된 경로/타입의 MIR 변조 검사 11건, 인터프리터 및 코덱(codec) 직렬화/역직렬화 검증, 중첩 store가 포함된 캐시 all-hit를 모두 통과했습니다.
- 기존 직접 필드·래퍼·복합 대입과 토큰 예제의 Windows 네이티브 회귀 테스트를 통과했습니다.
- 관련 semantic, MIR, interpreter, C backend, codec, packageartifact 테스트와 Go vet 검사를 모두 통과했습니다.
- 공개 CLI의 check 명령, 잠금 기반 일반/릴리스 build/run 및 portable native 테스트 12회를 정상 통과했습니다.

초기 테스트 중 부호 있는(signed) 나눗셈 오버플로의 기댓값 이름이 기존 규격과 불일치했던 테스트를 바로잡았습니다. 또한 잘못된 상수 시프트 연산 시 MSVC C4293 빌드 오류가 발생하던 C 코드 생성 로직을 개선했습니다. 범위 검사는 원래 값을 정확히 검사하고 트랩을 발생시키도록 유지하며, 검증 이후 도달할 수 없는 C 시프트 표현식에만 안전한 더미 값을 사용하도록 처리했습니다.

상세 실행 로그와 컴파일러, SDK, 소스 및 실행 바이너리 해시는 `docs/ops/evidence/nested-field-store-20261004.json`에 기록되어 있습니다.

## ADR 0443: 구조체 필드 전체 대입

`rebase`는 이제 `token.position = Span { ... }`으로 복사한 토큰의 구간을
한 번에 바꾼다. 직접·중첩 필드의 정확한 타입 대입을 허용하며, 원본 벡터와
치환에 사용한 값은 독립적인 복사 값이다. 참조 수신자는 RHS 전에 선택하고
재바인딩 뒤에도 원래 대상에 저장한다. RHS 실패는 최종 치환을 수행하지
않으며, 실패 이전에 RHS가 수행한 부수 효과를 되돌리지는 않는다.

Windows 일반·릴리스에서 복사/평가 순서/참조 선택 성공 프로그램과 런타임
RHS overflow 프로그램을 실행해 4개 결과가 통과했다. 공개 CLI `check`,
일반·릴리스 `build`/`run`과 정상·오류 입력 12회도 통과했다. 소스 거부,
잘못된 MIR, 인터프리터, codec roundtrip, package warm-cache 및 관련
패키지 검사와 Go vet를 확인했다. 증거와 이미지 해시는
`docs/ops/evidence/plain-struct-field-store-20261004.json`에 기록했다.

## ADR 0443: 구조체 필드 전체 대입

`rebase` 함수에서 `token.position = Span { ... }` 구문을 통해 복사된 토큰의 구간(Span)을 한 번에 대입할 수 있도록 개선했습니다. 직접 및 중첩 필드에 대한 엄격한 타입 대입을 지원하며, 원본 벡터와 대입에 사용되는 값은 서로 독립적인 복사본입니다. 참조 수신자는 우변(RHS) 평가 전에 미리 결정되며, 우변 평가 중 재바인딩이 일어나더라도 최초에 선택된 원래 대상에 정상 저장됩니다. 우변 평가가 실패하면 최종 대입은 수행되지 않으며, 실패 전 우변에서 발생한 부수 효과는 롤백되지 않습니다.

Windows 기본 및 릴리스 빌드에서 복사 독립성, 평가 순서, 참조 선택 검증과 런타임 우변 오버플로 트랩 테스트를 모두 통과했습니다. 공개 CLI `check` 및 일반·릴리스 `build`/`run` 테스트 12회를 정상 통과했으며, 소스 거부, 잘못된 MIR 탐지, 인터프리터, 코덱 왕복 직렬화, 패키지 웜 캐시 검사 및 관련 패키지 Go vet 검증을 완료했습니다. 상세 검증 기록은 `docs/ops/evidence/plain-struct-field-store-20261004.json`에서 확인할 수 있습니다.

## ADR 0444 후속 개선: 상수 연산 점검

앞선 ADR 0443에서 발생했던 우변(RHS) 상수 오버플로 시 MSVC C4702(도달할 수 없는 코드) 경고로 인한 릴리스 빌드 실패 문제를 해결했습니다.
개선 후 동일한 소스에 대해 공개 CLI `check`와 일반·릴리스 빌드가 정상적으로 완료되며, 실행 시 기대한 대로 `integer-overflow` 트랩(종료 코드 5)을 정확히 반환합니다.
Windows 네이티브 환경에서 총 20회의 실행 결과를 검증했습니다. 상수 증명 범위는 동일 블록 내의 스칼라 단순 복사로 한정하며, 간접 쓰기나 미지의 연산, 재지정을 만날 경우 불확실한 상수 정보를 안전하게 폐기합니다. 부수 효과 검증 픽스처를 통해 트랩 발생 전의 출력만 정상 생성되고 이후 출력은 차단됨을 확인했습니다. 관련 증적은 `docs/ops/evidence/constant-checked-c-20261004.json`에 보관되어 있습니다.

## ADR 0445: 가변 필드 대여 지원

`analyze` 함수에서 복사된 지역 토큰의 `local.position`을 `ref mut Span`으로 대여하여 `rebase(position, origin)`에 전달합니다. `rebase` 함수는 시작 및 끝 필드에 대해 checked 복합 대입을 수행합니다. 함수 호출 완료 후 자식 대여의 최종 사용(last-use)이 끝나면 지역 토큰의 필드를 다시 읽어 검증합니다. 원본 공유 벡터와 출력 결과는 그대로 보존되며, 모든 핵심 계산은 Fairy C 소스가 직접 수행합니다.

직접·중첩·그룹 필드 대여는 일반(plain) 구조체 그래프와 이름이 명시된 가변 지역 루트 및 기존 `ref mut` 수신자로 제한됩니다. 자식, 별칭, 후손 대여가 활성 상태인 동안 부모, 루트, 형제 노드에 접근하면 컴파일 오류(E2101)가 발생하며, 지역 소유자로부터 유래한 반환 시도는 E2102로 차단됩니다. 반환 함수 및 Option/Result를 경유하는 자식 필드 역시 동일한 보호 규칙이 적용됩니다. 리소스, 배열 원소, 함수 호출 결과, 포인터 역참조 루트 및 복수의 가변 형제 대여 동시 보유는 안전을 위해 허용되지 않습니다.

공개 CLI `check`, 잠금 기반 일반/릴리스 `build`/`run`, 정상 및 오류 입력에 대한 네이티브 테스트 12회를 통과했습니다. 상세 실행 증적은 `docs/ops/evidence/mutable-field-example-20261004.json` 및 `docs/ops/evidence/mutable-field-borrow-20261004.json`에 기록되어 있습니다.

## ADR 0446: 가변 구조체 참조에서의 공유 필드 대여

`rebase(ref mut Span position, usize origin)` 함수에서 시작과 끝 필드를 `ref usize`로 공유 대여하여 기존 길이를 안전하게 읽어옵니다. 마지막 공유 참조 사용이 끝난 후 부모 필드를 보정하고 길이가 유지되는지 검사합니다.

직접·중첩·그룹 필드 투영은 이름이 명시된 가변 참조와 일반 구조체 그래프에 한해 허용됩니다. 활성 상태인 공유 자식, 별칭, 반환값 또는 Option/Result가 존재하는 동안에는 부모 및 형제 노드에 대한 쓰기 시도가 컴파일 오류(E2101)로 차단됩니다. 반면 공유 읽기와 복수의 공유 형제 대여는 안전하게 공존할 수 있습니다. 참조 변수 재지정 시에도 먼저 생성된 자식 대여는 원래 소유자를 계속해서 올바르게 가리키고 보호합니다.

관련 semantic, MIR, C emission, interpreter 테스트 86건과 컴파일러/코덱 및 기존 가변 필드·공유 재대여 회귀 테스트 64건을 모두 통과했습니다. 상세 실행 증적은 `docs/ops/evidence/shared-field-example-20261004.json` 및 `docs/ops/evidence/shared-mutable-field-borrow-20261004.json`에서 확인할 수 있습니다.

## 이전 적용: ADR 0449 원본 벡터 원소의 필드 대여

`src/main.fy`에서 `vec::view_mut<Token>`을 생성하여 `tokens::rebase_segment`에 전달하도록 구현했습니다. 이 함수는 `ref mut segment[i].position`을 통해 벡터에 저장된 Span을 직접 대여하여 첫 번째 토큰의 시작 위치를 기준점만큼 차감합니다. 선행 공백이 포함된 입력에서도 첫 번째 토큰의 시작 오프셋은 정확히 0으로 보정되며 각 구간 길이는 온전하게 보존됩니다. 기존에 복사본 Token을 수정하던 불필요한 우회 경로는 제거되었으며, 정규화 후에는 기존 공유 뷰와 반복 순회를 통해 통계를 계산합니다.

토큰 위치 정보는 렉서 직후에는 원본 바이트 오프셋이며, 정규화 이후에는 첫 번째 토큰을 기준으로 한 상대 오프셋으로 변환됩니다. CLI의 토큰 수, 숫자 합계, 첫 구간 출력 결과는 기존 규격과 완벽히 일치합니다.

Windows 일반 및 릴리스 빌드에서 총 26건의 네이티브 테스트(13개 입력 케이스)를 정상 통과했습니다. 상세 실행 결과는 `docs/ops/evidence/indexed-field-example-20261004.json`에 기록되어 있습니다.

## 현재 적용: ADR 0450 가변 구조체 뷰 순회

`rebase_segment` 내부의 수동 인덱스 및 while 루프를 `for (let ref mut Token token in segment)` 구문으로 개선했습니다. 각 `token`은 벡터에 저장된 원소를 직접 가리키며, `ref mut token.position`으로 Span을 대여하여 좌표를 정규화합니다. 첫 번째 토큰 시작 위치의 0 보정과 각 구간 길이의 보존을 확인했습니다. 마지막 사용이 완료되면 자식 대여가 자동으로 해제되며, 이후의 공유 분석 단계와 CLI 출력 형식은 기존 규격을 그대로 유지합니다.

Windows 일반 및 릴리스 환경에서 총 26건의 네이티브 테스트를 모두 정상 통과했습니다. 상세 실행 로그와 바이너리 해시는 `docs/ops/evidence/mutable-struct-for-example-20261004.json`에 기록되어 있습니다.
Linux 네이티브 환경에 대한 전체 실행 검증은 추후 일괄 진행할 예정입니다.
