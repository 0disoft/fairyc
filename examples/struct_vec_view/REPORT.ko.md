# 명목 구조체 Vec 뷰 구현 결과

2026-10-04, SDK stage0.84의 공유 명목 구조체 뷰
`vec::view<T>(ref Vec<T>) -> ref T[]`를 구현했다. 초기화된 원소 구간만 대여하고
할당이나 원소 복사는 없다. 길이와 경계는 원소 개수를 세며, 빈 zero-backed 벡터와
빈 하위 구간도 유효하다.

`T`는 이미 지원하는 정수 다섯 종(`u8`, `i32`, `i64`, `u32`, `usize`) 중 하나일
수 있고, 이 경우 기존 타입별 정수 뷰를 그대로 쓴다. 또는 필드가 전부 평범한
스칼라(`bool`, `u8`, `i32`, `i64`, `u32`, `usize`)인 실제 비어있지 않은 명목
구조체다. 명목 원소에서는 `Token` 뷰를 레이아웃이 같은 `Other` 뷰로 재해석할 수
없고, 중첩 구조체·배열·리소스·빌림·raw 포인터·열거형 필드는 거부한다. 공유 뷰만
제공하므로 `ref mut` 구조체 슬라이스, 고정 배열 변환, 구조체 for-in은 없다.

인덱스는 구조체 값 하나를 통째로 복사하고 `view[i].field` 읽기는 허용하지만
원소·필드 대입은 거부한다. `var ref Token[]` 바인딩 자체는 다른 뷰로 다시 대입할
수 있다. 복사한 가변 지역 변수는 소유자와 독립적이며, 예제가
소유자를 clear하는 건 아니고 네이티브 fixture가 clear 후에도 복사본을 그대로 읽는지
확인한다. 살아있는 뷰는 소유자 전체를 공유 대여하므로 이동·교체·재할당·구조 변경
(효과 없는 `reserve`/`truncate` 포함)이 마지막 사용까지 막히고, 인덱스·슬라이스
경계는 소유자를 변경할 수 없다. ADR 0415의 형제·조상 규칙을 그대로 따른다.

## 예제

`src/tokens.fy`의 제한된 ASCII 렉서가 식별자·십진 정수·`+`·`=`·`;`를
인식하고 ASCII 공백을 무시한다. 음이 아닌 i64 리터럴과 합계는 overflow를 검사한다.
`src/main.fy`는 `Vec<Token>`을 만들고 공유 뷰와 첫 세미콜론까지의 앞부분 구간을
읽어 토큰·식별자·숫자 개수와 숫자 합계를 출력한다. 인자가 없으면 내장 소스를 분석해
합계 `4000000007`을 출력한다.

선택 인자는 분석할 ASCII 소스다. 4095 UTF-8 바이트와 토큰 128개로 제한하며, 잘못된
바이트·overflow·한도 초과·할당 실패는 진단과 함께 종료코드 2로 끝난다. 문법이나 식
평가는 하지 않고 렉싱과 산술 통계만 수행한다.

## 검증

Windows 네이티브 일반·릴리스에서 구조체 뷰 각 8케이스(성공 3, `bounds` trap 5)와
토큰 분석기 각 12케이스가 통과해 구조체 뷰 16개, 토큰 24개 네이티브 테스트가
통과했다. 공개 CLI 하네스는 17회 호출(check, locked 개발·릴리스 build/run, 네이티브
결과)이 모두 통과했고, `TestStruct(VecView|Token)`(정수 별칭 5종을 확인하는
`TestStructVecViewGenericIntegerAliases` 포함)와 직렬화 패키지 4개, `go vet`도
통과했다. 원시 영수증은 `.cache/struct-vec-view-native`,
`.cache/struct-token-native`에 있고, 최종 검증 영수증은
`docs/ops/evidence/struct-views-20261004.json`에 컴파일러·SDK·소스·EXE
해시와 원시 호출 결과로 남겼다.

재현은 예제 디렉터리에서 `python verify.py /절대/경로/fairyc`로 하고, Go 테스트는
저장소 루트에서
`bun tools/run-go.ts test ./internal/cli -run '^TestStruct(VecView|Token)' -count=1`로
돌린다. Linux 실제 실행은 이후 일괄로 미룬다.

## 한계

릴리스된 컴파일러나 타깃 성숙도·성능 주장이 아니다. 증거에 쓴 컴파일러는
`1aeb475b` 기반의 dirty 작업 트리다. 언어 `/20`, 런타임 ABI `/0`, 문법,
MIR·아티팩트·인터페이스 스키마와 C 런타임 심볼은 그대로이고 SDK 버전과 의존
식별자만 갱신한다. 일반 임의 원소 슬라이스, 가변 구조체·소유 슬라이스, 사용자 정의
제네릭 집계 승격은 허용하지 않는다. PS1 runner, 설치, CI runner, 벤치마크, push는
추가하지 않았다.
