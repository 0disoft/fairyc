# Local registry, update and Git preparation v1

Status: Go Stage 0 experimental preparation commands, ADR 0560. These commands
are not yet exposed by the Fairy-authored candidate CLI. Existing exact source
plans, manifests, graph locks, fetch behavior and build networking are unchanged.

```text
fairyc experimental registry-resolve trust.json catalog.json signature.json requests.json
fairyc experimental registry-update trust.json catalog.json signature.json requests.json fairy.sources.json
fairyc experimental git-snapshot local-repository full-immutable-commit snapshot.zip
```

JSON inputs and ZIP output use canonical portable paths under the current
workspace. The repository argument can be an explicit absolute local path, or
workspace-relative. Every command prints one JSON receipt/proposal on success.
Registry commands only read files. Git preparation creates an output exclusively;
an existing output is never replaced. No command applies an update, changes a
trust floor, downloads a catalog, checks out code or executes a package.

## Reviewed trust and detached signatures

Trust document (placeholders below are not usable keys):

```json
{"schema":"fairyc.registry-trust/v1","minimumSequence":7,"keys":[{"id":"publisher","publicKey":"<64 lowercase hexadecimal digits of a reviewed Ed25519 public key>"}]}
```

Catalog:

```json
{"schema":"fairyc.registry/v1","sequence":7,"expires":"<future UTC RFC3339 timestamp ending in Z>","packages":[{"packageUid":"example.math","version":"1.2.0","url":"https://packages.example/math-1.2.0.zip","sha256":"<64 lowercase hexadecimal digits of the reviewed archive>"}]}
```

`packages.example` is illustrative, not an installed/default registry. Signing is
performed by the publisher with its own private key, over the **exact catalog
file bytes**, prefixed by UTF-8 `fairyc.registry/v1` and one zero byte. Signature
document:

```json
{"schema":"fairyc.registry-signature/v1","keyId":"publisher","signature":"<128 lowercase hexadecimal digits of the detached Ed25519 signature>"}
```

No private key is read/generated by these commands. Unknown keys, malformed or
changed signed bytes, unknown/duplicate/missing JSON fields, expired catalogs
and sequences below the explicit floor reject before resolution. Expiry uses
the caller's current UTC clock. The floor is a reviewed local value, **not an
automatically maintained rollback database**. Advance it deliberately after
review; rotate/revoke keys by explicitly editing the local trusted-key list.
There is no key discovery, TOFU, revocation service or transparency log.

Bounds: 16 KiB trust, eight keys, 1 KiB signature, 256 KiB catalog, 256 distinct
UID/version releases; canonical stable uint32 SemVer components, absolute HTTPS
archive URLs and lowercase SHA-256 digests. Ordinary fetch later verifies both
archive bytes and manifest identity/language. A signed catalog does not grant
hooks or arbitrary filesystem paths.

## Ranges and exact output

Requests:

```json
{"schema":"fairyc.registry-requests/v1","packages":[{"path":"vendor/math","packageUid":"example.math","version":"^1.0.0"}]}
```

The highest matching version is selected numerically, independent of catalog
order. Exact `1.2.3`, caret `^1.2.3` and tilde `~1.2.3` are admitted. Caret uses
the first nonzero component as its compatibility bound (`^0.2.3 < 0.3.0`,
`^0.0.3 < 0.0.4`). Tilde stays below the next minor. Prereleases/build metadata,
wildcards, `latest`, inequalities, unions and transitive dependency solving
are not admitted by this first resolver; existing manifest exact-version syntax
is unchanged.

`registry-resolve` emits `fairyc.registry-resolution/v1` with `catalogSha256`,
`sequence` and `sourcePlan`. The latter is the existing `fairyc.sources/v1`
document, with exact versions/URLs/hashes and at most 32 packages/64 KiB.
Review and copy that plan deliberately; separately reconcile the root's explicit
workspace members and exact dependency versions before ordinary fetch/build.

`registry-update` emits `fairyc.package-update-proposal/v1`: the canonical sorted
current-plan hash, resolution and before/after pin records. It preserves the
complete path/UID set, refuses downgrades and refuses a new digest for an existing
exact version. A same-digest URL mirror change can be proposed. It does not
write the manifest, source plan, graph lock or trust document.

## Immutable local Git snapshots

The repository must be its explicit worktree root and the commit a full lowercase
40- or 64-digit object ID. Branches, tags, abbreviations and implicit parent
repositories reject. Git's tree and batch blob readers are used instead of
`git archive`, checkout or filters, so working-tree edits and export attributes
cannot change the selected committed bytes. Ambient Git environment, replacement
objects and lazy fetching are disabled. The local Git executable/object database
remains the object reader; this is not a forensic verifier of a hostile database.

Before ZIP entry creation, each blob is rehashed over Git's `blob <size>` header,
NUL and actual bytes, using SHA-1 for 40-digit IDs or SHA-256 for 64-digit IDs.
A matching batch header alone does not establish content identity. Digest
mismatch rejects the snapshot, including same-size substitutions. Commit/tree
object interpretation still trusts the local Git reader. This does not add
publisher authentication. Optional per-operation blob I/O callbacks retain host
defaults; the existing context is checked during reads, hashing and ZIP writes.
Cancellation is cooperative and cannot interrupt an already blocked host call.
The Go Git-process consumer separately owns its stdout pipe. Caller cancellation
closes that pipe and stops the producer, releasing a blocked read even when a
descendant retains the write end. This is required before `Cmd.Wait`: its existing
wait delay alone does not bound a consumer blocked before entering Wait. Every
successfully started producer is waited once, the output closes once, and the
cancellation watcher finishes before the consumer returns. Read/close/wait errors
and the caller's cancellation cause are retained; cancelling a rejected producer
does not itself relabel a parse failure as caller cancellation. Per-call internal
options default to Background and the host stdout/start/wait operations. Injected
output streams must release pending reads on Close, and process operations must
retain their existing ownership and cancellation semantics. Descendant termination
is not claimed; closing the owned read end prevents it from retaining this reader.

Only regular blob modes are accepted; symlinks/gitlinks/submodules, nested VCS
metadata, unsafe/case-colliding paths, invalid package manifests and nested
workspaces reject through the existing archive validator. Bounds remain 4,096
files, 8 MiB/file, 64 MiB expanded, 16 MiB ZIP and a shared 30-second Git operation
budget. ZIP timestamps/modes are normalized. Files are ordinary non-executable
data. No publisher authentication is inferred from a commit or generated hash.

The `fairyc.git-snapshot/v1` receipt includes the commit, package UID/version,
language, file count and ZIP SHA-256. Validate all bytes before publication; a
same-directory synced temporary is hard-linked without replacement, then cleaned
up. Hard-link support is required. A directory-sync failure can report failure
after publication; an already published valid file is not erased on that path.

Remote Git transport/authentication, service hosting, key distribution and
automatic update application remain separate work.
