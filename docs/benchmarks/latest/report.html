Scope

Rust small-dev sets debug = "line-tables-only" and incremental = false. Zig release uses ReleaseFast. C dev requests debug information; Fairy C development does not promise equivalent debugger support. The Zig and C fixtures use libc stdin/stdout, Rust uses its standard library, and Fairy C uses its SDK. These are build workflow measurements with different runtime and debugging facilities.

Reading the results

  • Each profile, workload and repetition begins with empty dedicated project outputs, Cargo home, Zig global cache, Fairy C user cache and temporary directory. Toolchain files and OS caches remain installed.
  • Charts include passed sequences only. The table preserves failed and unavailable cases; they do not become zero-byte results.
  • File lengths count each regular pathname once across disjoint measured roots. Hard links can occupy less physical storage; sparse files, filesystem compression and allocation units are not measured. Symlinks in measured output roots are rejected.
  • Separate PDB/debug files have their own bucket. Debug data embedded in an executable or object remains in that file's bucket. Rust dependency artifacts are part of intermediate outputs; these fixtures have no third-party packages.
  • Rust cleanup uses Cargo clean. For Fairy C/C the tool removes project build output; for Zig it removes zig-out and .zig-cache. Shared experiment caches are retained and measured after cleaning. Cleanup policies differ and are recorded per sample.
  • Footprint components use arithmetic means across repetitions so stacked totals add up. Growth curves use medians at each edit. With one repetition, all numbers are individual observations. Build order is fixed; timing is descriptive and subject to host noise.
  • Steady-state disk use excludes temporary files already deleted during compilation. Runtime speed, peak disk use, peak memory, downloaded dependencies and toolchain installation sizes are outside this measurement.
