# ADR 0266: Add native testing to the starter guide

- Status: Accepted
- Date: 2026-08-05
- Supersedes generated README bytes in: ADR 0208
- Depends on: ADR 0208, ADR 0265
- Implementation: `internal/projectscaffold/`

## Context

Starter v3 generates a valid semantic test and tells users to run `fairyc test --locked`, but its
guide predates the explicit Windows native-test lane. A new Windows user can build and run the
program yet cannot discover that the same checked-in `@test fn void` can be compiled and executed
through MSVC without rewriting it as `main`.

The existing semantic command must remain the default because it is fast, deterministic, and
host-independent. Native testing is an additional Windows validation step, not a replacement or a
new generated source shape.

## Decision

1. Keep the exact five-file set, manifest, source, test bytes, package identity, no-overwrite
   containment, lock behavior, success line, exit codes, rollback boundaries, and run/build guide
   unchanged except for the generated README text described here.
2. Label `fairyc test --locked` as the fast semantic-interpreter command.
3. Add `fairyc test --native --locked` to the existing Windows block before run/build and state that
   it compiles every test into a separate temporary Windows image.
4. Do not make native testing automatic during project creation, select release mode by default,
   retain a test image, add a target flag, or change existing projects.

## Evidence

- Exact-byte scaffold tests freeze the new README while retaining all other generated bytes.
- Generated-project CLI integration continues to check, lock, and run the semantic test.
- The separately built compiler's Windows smoke requires the new guide line, then executes the
  generated starter's native trap-isolation test through the stable command.

## Consequences

New Windows starters expose both test engines without increasing the generated source or manifest
surface. Generated README bytes change, so this is starter v4 rather than a silent edit to v3.
Existing projects remain untouched and their prior instructions remain valid.
