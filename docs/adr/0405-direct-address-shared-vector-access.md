# ADR 0405: Direct-address shared vector access

- Status: Accepted SDK implementation; C-relative runtime gate still open
- Date: 2026-09-24
- Depends on: [owner-bound storage borrows](0389-owner-bound-storage-borrows.md),
  [mutable vector element access](0400-mutable-vector-element-access.md)

## Decision

SDK `0.0.0-stage0.67` keeps the public `std::vec::at<T>(ref Vec<T>, usize) -> ref T`
contract and first checks `index < value.length`. Its authenticated private
source then computes `storage_element_address<T>(value.data, index)`, rejects a
null result and returns `storage_borrow<T>(value, slot)`. The checked private
operation retains the concrete `T` layout and emits null and offset-overflow
guards. The shared result remains tied to the vector owner's loan; callers
cannot safely move or mutate the vector before the reference's last use.

The previous implementation called `fy_private_vector_element_slot_v0` for
each read. The private C symbol stays in the runtime for objects generated by
older SDKs, but new SDK source no longer declares or calls it. The new source
does not repeat the C helper's full descriptor validation on each read. Safe
construction, push and reserve own descriptor integrity and initialized-prefix
state; a forged descriptor requires unsafe or private code. This change does
not claim instruction-for-instruction equivalence on malformed unsafe inputs.

Language revision `/19`, public API shape, runtime ABI `/0`, MIR version and
interface schemas do not change. The SDK version and exact source digest do;
workspaces importing `std::vec` refresh their SDK lock. The compiler-private
read-only vector iteration source gate in [ADR 0404](0404-read-only-sdk-vector-iteration-candidate.md)
remains closed.

## Evidence and remaining gate

Before this change, the [indexed](../ops/c-budget-vector-read-index-20260924.md)
and [private candidate](../ops/c-budget-vector-read-candidate-20260924.md)
four-element read kernels exceeded the cumulative 1.08 C-relative runtime
limit, and [generated-code inspection](../ops/vector-read-access-inspection-20260924.md)
found the same private slot call in their optimized inner loops.

Existing compiler SDK candidate tests cover owner-bound scalar and resource
reads, mutation and move rejection, out-of-range traps and low/optimized native
execution. Both indexed and private-candidate C smoke lanes pass ten boundary
executions after this implementation change. A diagnostic five-pair run showed
paired runtime medians of 1.08341 (indexed) and 1.08135 (private candidate)
relative to the unchanged C workload; optimized EXE ratios were 1.01824.
Those preliminary results are improvements but still above 1.08 on the paired
median criterion. The diagnostic disassembly no longer contains a call to the
old slot helper. Full post-commit cost evidence, timing stability, the real
lexer workload and unused-feature overhead remain separate gates. No stable
source admission follows from this SDK improvement.
