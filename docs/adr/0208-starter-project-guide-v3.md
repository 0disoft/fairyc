# ADR 0208: Align the generated starter with program-facing run v2

- Status: Accepted
- Date: 2026-07-23
- Supersedes generated bytes in: ADR 0206
- Depends on: ADR 0207
- Implementation: `internal/projectscaffold/`

## Context

Starter v2 returned 42 from `main` because stable run v1 converted that value into a compiler-owned
receipt and exited successfully. Under program-facing run v2, 42 correctly becomes the shell status,
which makes the untouched starter look unsuccessful. Its generated guide also tells users to build
and launch a retained executable for output even though stable run now forwards streams.

## Decision

1. Keep the exact five-file set, command spelling, explicit identity, no-overwrite containment,
   manifest, public `answer()` value, semantic test, lock ownership, success line, exit codes, and
   rollback boundaries unchanged.
2. Change only the private starter entry to `return answer() - 42;`. The program still exercises the
   public function and returns zero when its documented answer is correct; the semantic test keeps
   asserting the independently visible value 42.
3. Update the exact generated README to state that stable run forwards stdout/stderr and returns
   `main`'s `i32` as process status. Keep the retained build example as an optional native artifact
   path.
4. Change the safe `std::io` next step to ordinary check followed by locked release run. The complete
   source fence already returns zero only after writing the full message.
5. Do not add a selectable template, upgrade command, program argument, stdin, target, or toolchain
   option. Existing projects remain untouched.

## Evidence

- Exact-byte scaffold tests freeze the new entry and README.
- Generated-project CLI integration still checks, locks, tests, and compiles the actual README source
  fence.
- The separately built compiler's Windows smoke verifies the new guide text and untouched starter
  status zero, then executes the safe stdout example through stable run with exact bytes and status
  zero.

## Consequences

A newly created project now follows conventional process-success semantics without losing the
answer-42 compiler and test proof. Generated README bytes change again, so this is starter v3 rather
than a silent correction to v2.
